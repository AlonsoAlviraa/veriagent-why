# Sponsor technology

**Zetaris (data, default backend).** `app/adapters/zetaris.py` connects to Zetaris Lightning over JDBC (JayDeBeApi + the Zetaris JDBC driver). The synthetic data is loaded by `scripts/zetaris_load.py` into a Postgres datasource and REST tables federated into a SchemaStore container, exposed as five views: `v_orders`, `v_returns`, `v_tickets`, `v_logistics`, `v_promotions`. The Retriever's SQL templates, the Evidence Evaluator's re-queries and the Traceability Check's checks all run through this adapter, and every citation in the memo points to rows it returned. When Zetaris is not configured, the same SQL runs on a local DuckDB snapshot (SAMPLE_MODE); this fallback is explicit, logged (`data_fallback`) and printed in the memo.

**Meterless (cognition).** The open-source H-MEM and Markovian reference engines (Apache-2.0, pinned commit, vendored in `vendor/meterless/`) run in node through `meterless_bridge/`. H-MEM holds the evidence graph: hypotheses, retrieval calls, evidence and support/refute edges, with a per-run trust ledger (`hmem-ledger-<run_id>.jsonl`); the Planner recalls from it. Markovian runs the Evaluator → Planner investigation rounds (one chunk per round, `[STATE_CHECKPOINT]` carryover, `[TASK_COMPLETE]` stop). If node is missing, a local non-Meterless graph is used and the fallback is logged; `METERLESS_REQUIRED=1` makes it fatal.

**Meterless Nightshift 1.2.7 (model provider).** The product's primary model provider is a local Nightshift 1.2.7 proxy (`LLM_PROVIDER=nightshift`, `app/nightshift.py`): S1 routes to `nemotron-3.5-lightning-30b-a3b` (reasoning off) and S2 to `nemotron-3-ultra-550b-a55b` (thinking off), pinned per call. Every call writes a receipt (`logs/receipts-<run_id>.jsonl`: agent, request id, requested/routed model, latency, fallback flag). Live receipts from 25 Oct 2026 (3 demo scenarios, run on the DuckDB snapshot, not live Zetaris) are in `eval/nightshift_live/`. `app/nightshift_sim.py` is a separate test-only simulator of the same API, not Nightshift.

**NVIDIA (models).** Nemotron models on hosted endpoints, no local GPU: through Nightshift, Lightning 30B (S1: agentic retriever tool loop, relevance filter, Evidence Evaluator) and Ultra (S2: Planner, Cause Analyst, Writer); with `LLM_PROVIDER=nvidia` (direct NVIDIA endpoint, used for the 22 Oct dev-split run) `nvidia/nemotron-3.5-super-vl-120b-a12b` (S2) and `nvidia/nemotron-3.5-lightning-30b-a3b` (S1), `nvidia/nemotron-3-embed-1b` (retrieval and H-MEM embeddings). Model outputs are schema-validated; numbers come only from SQL.

**What is unique.** The Evidence Evaluator re-queries the data itself and can send the Planner back for another round, and a deterministic Traceability Check blocks any claim, or any model-written number, that the data does not support. Confidence is a formula over evidence, not a model guess.
