# Audit trace (`audit.json`, schema `audit-trace/1`)

One JSON document per benchmark case that shows the whole flow: what each step received, what the model or
the controller decided and why, which evidence and claims survived the Traceability Check, how the final answer was
composed (including deterministic post-format transformations) and how it was scored.

- Schema: [`docs/audit_trace.schema.json`](audit_trace.schema.json) (JSON Schema 2020-12).
- Builder: `bench/audit_trace.py` (one case), `bench/audit_cases.py` (the documented example set + `audit_all.json`).
- Tests: `tests/test_audit_trace.py` (offline, no model calls).

## Rules

1. **Never invent.** Anything the run did not record is the literal string `"not_logged"`.
2. Values the builder derives from logged data are labelled `recomputed_by_audit` (e.g. whether a quoted
   TAT-QA evidence string is verbatim in the context; whether an InsightBench claim's cited ids exist and are
   not SQL errors; the deterministic-confidence formula re-evaluated on the logged inputs).
3. **Gold is isolated** in `case.eval_only`, labelled *never shown to any model*. Only the scorer reads it.
4. **No secrets.** Every trace is scanned (nvapi-/sk-/Bearer/api_key=/gh*_/JWT patterns); matches are replaced by
   `[REDACTED]` and counted in `secret_scan.redactions`.
5. The `narrative` is generated by fixed templates from the steps. No LLM.

## Fields

| Field | Content |
|---|---|
| `case` | bench, run, config, item_id, question, dataset_split, ts, code_rev; `eval_only.gold` (+ TAT-QA derivation) |
| `models[]` | role (`generator` / `verifier` / `judge` / `classifier` / `reranker`), real `model_id`, provider, calls (from `meter.providers` / `judge_meter.providers`) |
| `steps[]` | ordered; `type` in plan, route_decision, sql, retrieval, evidence_eval, requery, cause_analysis, writer, claim_gate, verify_retry_attempt, post_format, scoring; `summary`, `inputs`, `outputs`, `prompt_hash`, `prompt` (truncated to 2000 chars), `prompt_template_ref` (code location), `decision` {source, decision, state, action, reason, carryover} from the Markov controller, `latency_s`, `tokens`, `cost_usd`, `errors`, `retries` |
| `evidence[]` | id, source, query (SQL or question), result (≤600 chars), flags |
| `claims[]` | id, text, cited_evidence, traceable, gate_verdict (PASS/REJECT for TAT-QA; KEPT/DROPPED for InsightBench), why |
| `final_answer` | answer/insights + summary, `composed_from` {claims, evidence}, `post_format` [{field, before, after, rule}] |
| `confidence` | deterministic value, model self-reported value, formula, inputs, recomputed value |
| `scores` | EM/F1 (+raw) or ROUGE/judge, explainability metrics, `failure` (cause, code, Super category) from `failures_all.jsonl` |
| `totals` | per-item system and judge meters (calls, tokens, seconds, USD) |
| `llm_calls` | per-call records not matched to a step (new runs only) |
| `availability` | which detail groups were present in the source row |

## What existing runs (v2, markov-sample, battery) contain

| Detail | Status |
|---|---|
| Controller decisions (state/action/reason/carryover) | **logged** for `agent_mk*`; `fixed_policy` for plain configs |
| Gate rounds + reasons (TAT-QA), per-round insights/failed/summary_unsupported (InsightBench) | **logged** |
| Final answer, raw answer (before post-format), scale, expression, quoted evidence | **logged** (TAT-QA) |
| Kept claims with cited ids, dropped claims with unsupported numbers | **logged** (InsightBench) |
| Query results (`evidence_store`, truncated) | **logged** |
| Scores, explain metrics, deterministic + self confidence | **logged** |
| Item-level calls, tokens, seconds, USD, real provider:model | **logged** (per item, not per step; attributed to the step only when the item made exactly one call) |
| Prompts, prompt hashes, per-step latency/tokens/cost | **not_logged** |
| SQL text and planner/evaluator questions | **not_logged** |
| Calculator (NUMERIC route) expressions/observations; intermediate gate-round drafts | **not_logged** |
| Question text in the row | not in row; joined from the dataset by id |

## Logging hook for new runs

`/workspace/open-agent-hackathon/audit_trace_hooks.patch` (against the current `feat/markov-control` working
tree; `git apply --check` passes). It adds:

- `bench/llmio.py` `Meter`: one record per model call in `calls_log` (tag, prompt hash, prompt truncated to
  `AUDIT_PROMPT_CHARS`=2000, real provider:model, latency, tokens, cost delta, reply head, error), exported as
  `meter.trace_calls`. `AUDIT_TRACE=0` disables it. Prompts contain dataset text only; keys live in HTTP headers
  and never enter `messages`.
- `bench/tatqa.py`: every gate round stores its output (`gate[].out`); `agent_markov` returns `calc_history`.
- `bench/insightbench.py`: `queries_log` {qid: question, sql, first_error}; gate rounds store `drafts`.
- `bench/markov.py`: each decision gets a wall-clock `t` so it can be interleaved with model calls.
- `bench/run.py`: `question` and `code_rev` on every row.

The builder already consumes these fields when present (`attach_calls`, `queries_log`, `calc_history`, `drafts`).

## Usage

    python -m bench.audit_trace --results bench/results/tatqa-markov-sample.jsonl --config agent_mk \
        --id 8757782d-306d-4a0d-b22e-ab0f2b58171c --data data/bench --failures failures_all.jsonl --out audit.json
    python -m bench.audit_cases --results-dir bench/results --data data/bench --failures failures_all.jsonl --out audit_traces/

Example set (markov-sample run): TAT-QA 2 correct (EVIDENCE route with scale inferred, multi-span), 2 scale/format
failures (missing scale, rounding), 1 citation failure, 1 arithmetic failure; InsightBench 1 good (judge 0.8),
1 paraphrase, 1 SQL error, 1 wrong insight.
